# 🚀 Hackathon — Frameworks Front-end

## Desenvolvimento do Projeto

### 🎯 Desafio

Cada equipe deverá desenvolver uma **aplicação web funcional** que apresente uma solução para um problema relacionado a **um dos 17 Objetivos de Desenvolvimento Sustentável (ODS)** da ONU.

O tema é livre, porém a solução deverá apresentar claramente:

- o problema identificado;
- o ODS relacionado;
- o público-alvo;
- a proposta de solução;
- o valor gerado pela aplicação;
- a aplicação desenvolvida em um framework Front-end.

O projeto deverá ser desenvolvido integralmente durante o período do Hackathon.

---

# 👥 Organização

- Equipes de **4 integrantes**;
- Todas as equipes deverão desenvolver uma solução relacionada aos **17 ODS**;
- Cada equipe poderá escolher livremente o ODS e o problema que deseja solucionar;
- O framework Front-end será de livre escolha;
- O uso de APIs e CRUD é opcional;
- O uso de Inteligência Artificial é permitido.

---

# ⏱️ Tempo

**Tempo total de desenvolvimento: 4 horas.**

Todo o processo deverá ser realizado durante o período determinado para o Hackathon.

A equipe deverá iniciar o projeto no início da atividade e realizar o desenvolvimento, documentação e publicação dentro do prazo estabelecido.

---

# 📋 Etapas do Projeto

## 1. Definição do problema

A equipe deverá escolher:

- um dos 17 ODS;
- um problema relacionado ao ODS escolhido;
- o público afetado pelo problema;
- a necessidade identificada;
- o objetivo da solução.

### Entrega

```text
ODS escolhido:
Problema:
Público-alvo:
Necessidade:
Objetivo da solução:
```

---

## 2. Benchmarking

A equipe deverá realizar um benchmarking de **5 soluções existentes** relacionadas ao problema escolhido.

Para cada solução, deverá identificar:

- nome;
- funcionalidades;
- público-alvo;
- pontos positivos;
- pontos negativos;
- características que podem ser utilizadas como referência.

Ao final, a equipe deverá apresentar quais características foram utilizadas como referência para sua solução.

---

## 3. Proposta de Valor

A equipe deverá definir a proposta de valor da solução.

Deverá responder:

> **Qual problema resolvemos?**

> **Para quem?**

> **Como nossa solução ajuda?**

> **Qual valor ela entrega?**

---

## 4. Requisitos

A aplicação deverá possuir, no mínimo:

### Requisitos Funcionais

**10 requisitos funcionais.**

Exemplo:

```text
RF01 — O sistema deve permitir cadastrar um usuário.
RF02 — O sistema deve permitir consultar os dados.
RF03 — O sistema deve permitir visualizar...
```

### Requisitos Não Funcionais

**10 requisitos não funcionais.**

Exemplo:

```text
RNF01 — A aplicação deve ser responsiva.
RNF02 — A aplicação deve possuir interface acessível.
RNF03 — A aplicação deve apresentar tempo de carregamento adequado.
```

---

## 5. User Stories

Os requisitos deverão ser transformados em **histórias de usuário**.

Modelo:

```text
Como [tipo de usuário],
quero [ação],
para [objetivo/benefício].
```

Cada história deverá possuir critérios que permitam verificar se a funcionalidade foi implementada corretamente.

---

## 6. Prototipação

A equipe deverá criar um protótipo da solução antes ou durante o desenvolvimento.

O protótipo deverá possuir **no mínimo 10 telas**.

Deverá apresentar:

- fluxo de navegação;
- principais funcionalidades;
- estrutura das interfaces;
- componentes principais;
- versão responsiva ou adaptação para diferentes tamanhos de tela.

O protótipo deverá servir como referência para o desenvolvimento da aplicação.

---

## 7. Gestão do Projeto

A equipe deverá utilizar uma ferramenta de gerenciamento de projetos de sua escolha.

Exemplos:

- Trello;
- GitHub Projects;
- Jira;
- Notion;
- outra ferramenta equivalente.

O projeto deverá possuir **no mínimo 50 cards**.

Os cards deverão representar atividades reais realizadas durante o desenvolvimento.

Exemplos:

```text
Definir problema
Realizar benchmarking
Criar requisito
Criar user story
Criar wireframe
Criar componente
Implementar página
Implementar formulário
Integrar API
Testar responsividade
Corrigir bug
Criar documentação
Configurar deploy
```

Cards criados apenas para atingir a quantidade mínima não serão considerados.

---

## 8. Desenvolvimento

A equipe deverá desenvolver uma **aplicação Front-end funcional** utilizando um framework de sua escolha.

São permitidos, entre outros:

- React;
- Vue;
- Angular;
- Next.js.

A aplicação deverá apresentar:

- navegação funcional;
- componentes reutilizáveis;
- interface responsiva;
- organização do código;
- boas práticas de desenvolvimento;
- interação com o usuário;
- implementação das principais funcionalidades definidas nos requisitos.

---

## 9. Git e Versionamento

O projeto deverá ser versionado utilizando Git.

A equipe deverá realizar **no mínimo 30 commits significativos**.

Os commits deverão representar alterações reais no projeto.

Exemplos:

```text
feat: cria tela inicial
feat: implementa componente de busca
feat: adiciona formulário de cadastro
style: ajusta responsividade
fix: corrige validação do formulário
docs: atualiza README
```

Commits sem alterações relevantes ou criados exclusivamente para atingir a quantidade mínima não serão considerados.

---

## 10. Deploy

A aplicação deverá ser **publicada e acessível pela Internet**.

A equipe deverá disponibilizar no README:

```text
URL da aplicação:
URL do repositório:
URL do protótipo:
```

---

## 11. Documentação

O repositório deverá possuir um **README.md** contendo, no mínimo:

```markdown
# Nome do Projeto

## ODS

## Problema

## Público-alvo

## Proposta de Valor

## Benchmarking

## Requisitos

## User Stories

## Funcionalidades

## Tecnologias Utilizadas

## Framework Utilizado

## Como Executar

## Protótipo

## Aplicação

## Processo de Desenvolvimento

## Integrantes
```

A documentação deverá permitir compreender **o que foi desenvolvido, por que foi desenvolvido e como o projeto foi construído**.

---

## 12. Uso de Inteligência Artificial

O uso de ferramentas de Inteligência Artificial é **permitido**.

A equipe deverá registrar no README:

- quais ferramentas foram utilizadas;
- em quais etapas foram utilizadas;
- como contribuíram para o desenvolvimento.

Exemplo:

```markdown
## Inteligência Artificial

Ferramenta: ChatGPT

Utilização:
- geração de ideias;
- auxílio na criação de componentes;
- revisão de código;
- identificação de erros.
```

A utilização de IA não substitui a responsabilidade da equipe pelo código e pela solução entregue.

# ⏰ Regra de encerramento

Ao término das **4 horas**, o desenvolvimento será encerrado.

A avaliação será realizada considerando **o estado do projeto no momento do encerramento**.

Não haverá apresentação oral. A avaliação será realizada por meio dos artefatos produzidos, do repositório, da aplicação publicada e da documentação do processo.

---

# 🏆 Avaliação

A atividade será avaliada por uma **rubrica de 0 a 10 pontos**, considerando tanto o resultado técnico quanto o processo de desenvolvimento.

Os critérios serão definidos considerando:

- qualidade da solução;
- aderência ao problema e ao ODS;
- benchmarking;
- proposta de valor;
- requisitos;
- prototipação;
- gestão do projeto;
- desenvolvimento Front-end;
- utilização do framework;
- versionamento;
- deploy;
- documentação.

**A distribuição dos pesos e os níveis de desempenho serão apresentados na rubrica de avaliação.**
